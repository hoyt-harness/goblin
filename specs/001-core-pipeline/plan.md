# Implementation Plan: goblin Core Pipeline

**Branch**: `001-core-pipeline` | **Date**: 2026-08-10 | **Spec**: [spec.md](spec.md)

## Summary

goblin is a Go CLI binary that extracts keyframes and a timestamped transcript
from a local media file and writes a structured MANIFEST directory consumable
by Claude and editing pipeline tools. The pipeline has four stages — probe,
extract, transcribe, manifest — each independently invocable. v0.1.0 covers
local files, single-file invocation, and the full four-stage pipeline.

## Technical Context

**Language/Version**: Go 1.26.5

**Primary Dependencies**: stdlib only for goblin itself. Runtime tool
dependencies (not Go packages): `ffprobe`, `ffmpeg`, `whisper-cli`,
optionally `mkvextract` and `mediainfo`.

**Storage**: Filesystem. Output directory with JSON files and PNG frames.
No database.

**Testing**: `go test ./...` — unit tests per internal package; integration
tests in `test/` using small fixture media files.

**Target Platform**: Windows x64 (primary). Linux (future — no Windows-specific
code should be introduced without a build tag).

**Project Type**: Single-purpose CLI binary.

**Performance Goals**: Frame extraction and manifest writing must not be the
bottleneck. Transcription performance is GPU-bound (whisper); goblin's
overhead above whisper and ffmpeg should be negligible (<2s for any file size).

**Constraints**: No outbound network calls. No CGO (pure Go build). Single
binary with no runtime Go dependencies.

**Scale/Scope**: Single file per invocation, v0.1.0. Batch and URL support
are future extensions.

## Key Implementation Notes

### Stage Orchestration (main.go)

1. Parse flags → Config struct
2. Tool presence checks (exit 2 on failure)
3. Validate source file exists (exit 3 on failure)
4. Create output directory (exit 4 if exists without -overwrite)
5. Run probe → ProbeResult
6. If extract stage: run extract → []Scene, []Frame
7. If grid mode: run grid → []GridSheet
8. If transcribe stage: run transcribe → []TranscriptSegment
9. Run manifest → write all JSON files

### ffmpeg Scene Detection Invocation

```bash
ffmpeg -i FILE \
  -vf "select=gt(scene\,THRESHOLD),metadata=print:file=OUTDIR/.frame-meta" \
  -vsync vfr -q:v 2 \
  OUTDIR/frames/frame_%05d.png
```

Parse `.frame-meta` (key=value blocks separated by blank lines) to associate
each frame PNG with its `pts_time`. Delete `.frame-meta` after parsing.

### Audio Extraction Before Whisper

```bash
ffmpeg -i FILE -vn -acodec pcm_s16le -ar 16000 -ac 1 OUTDIR/.audio.wav
whisper-cli -m MODEL -f OUTDIR/.audio.wav -oj -ojf -of OUTDIR/transcript
```

Delete `.audio.wav` after whisper completes. Whisper produces `transcript.json`
directly (it appends `.json` to the `-of` path).

### Transcript Normalization

Whisper's JSON output is parsed and normalized into goblin's TranscriptSegment
schema before writing. The raw whisper JSON is not kept in the output directory.

### Cross-linking Scenes and Transcript Segments

After both extract and transcribe stages complete, goblin computes which
transcript segments overlap each scene's time range and populates
`SceneEntry.transcript_segments` with their indices. This cross-link is what
enables downstream editing tools to correlate visual scenes with spoken content
without re-parsing both files independently.

### Go Module

No external Go package dependencies in v0.1.0. If a JSON library is needed,
use `encoding/json` from stdlib.
